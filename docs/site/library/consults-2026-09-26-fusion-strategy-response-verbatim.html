# Brief:  high score = synthetic ; expensive error = real called synthetic (FA), 4x, pi=0.3
#         DCF_S1 = P_miss + 9.333*P_FA        (normalise by min(pi*Cmiss,(1-pi)*Cfa)=0.3)
# Shipped ASVspoof5 code: high score = bona fide ; Pspoof=.5, Cmiss=1 (bona fide REJECTED), Cfa=4 (spoof ACCEPTED)
#         unnormalised = Cmiss*(1-pi_s)*Pmiss_bona + Cfa*pi_s*Pfa_spoof = .5*Pmiss + 2*Pfa ; /min(.5,2)=.5
#         DCF_S3 = Pmiss_bona(=real rejected) + 4*Pfa_spoof(=spoof accepted)
print("S1 weights: P_miss(spoof called real) x1 , P_FA(real called synth) x9.333  -> expensive claim = 'synthetic' = HIGH score")
print("S3 weights: P_miss_bona(real rejected) x1 , P_fa_spoof(spoof accepted) x4  -> expensive claim = 'bona fide' = HIGH score")

pi_true=0.30
def block_cost(q, where, scenario):
    """cost added per unit block mass u; where in {'min','max'} of the SUBMITTED score"""
    if scenario=='S1':   # high = synthetic
        return q/pi_true if where=='min' else 9.3333*(1-q)/(1-pi_true)
    else:                # S3: high = bona fide, we flipped determinate scores
        return (1-q)/(1-pi_true) if where=='min' else 4.0*q/pi_true
rows=[]
for q in [0.05,0.10,0.20,0.30,0.50,0.70,0.80,0.90]:
    r={'q (spoof rate in block)':q}
    for sc in ['S1','S3']:
        cmin,cmax=block_cost(q,'min',sc),block_cost(q,'max',sc)
        r[f'{sc} cost@MIN']=round(cmin,3); r[f'{sc} cost@MAX']=round(cmax,3); r[f'{sc} best']='MIN' if cmin<=cmax else 'MAX'
    rows.append(r)
T=pd.DataFrame(rows); print("\n", T.to_string(index=False))
# break-evens
from scipy.optimize import brentq
q1=brentq(lambda q: block_cost(q,'min','S1')-block_cost(q,'max','S1'),1e-6,1-1e-6)
q3=brentq(lambda q: block_cost(q,'min','S3')-block_cost(q,'max','S3'),1e-6,1-1e-6)
print("\nbreak-even q*: S1=%.3f (put at MIN if q<q*)   S3=%.4f (put at MIN if q>q*)"%(q1,q3))
print(">>> DIRECTION-ROBUST WINDOW for 'indeterminate block at the MINIMUM submitted score': q in [%.3f, %.3f]"%(q3,q1))

Assumptions and Limitations

Assumptions

  • Best-team $\mathrm{minDCF}$ is assumed near 0.05 for the points-per-DCF slope (~63 points per unit DCF); the slope moves if the true best is much lower or higher.

  • Test set composition is assumed to match the stated prior: ~1,170 real and ~501 spoof out of 1,671, which makes one false alarm exactly 4× one miss.

  • Holdout composition is 1,858 real and 2,000 spoof, giving 0.0050 DCF per false alarm and 0.00050 DCF per miss.

  • The brief's cost structure is $\mathrm{minDCF}=P_{miss}+9.333P_{FA}$ at $\pi_{synth}=0.3$, $C_{fa}=4$, $C_{miss}=1$.

  • The shipped ASVspoof5 script is unmodified with $P_{spoof}=0.5$, $C_{miss}=1$, $C_{fa}=4$, and treats a higher score as bona fide, so the $4\times$ weight falls on spoof-accepted.

  • Indeterminate files are assumed to have internal spoof rate $q\approx\pi_{synth}=0.30$, with no evidence that any category exceeds $q=0.80$.

  • The fusion v0 table values (holdout, ITW, inner OOF, test share) are taken as reported and were computed without fitting on holdout, ITW or test.

  • All reported v3 numbers are post-band-match; the earlier VCTK null result is treated as confounded by the 7.2 kHz shortcut.

  • $\mathrm{minDCF}$ is invariant to any monotone transform of the scores, so only the ranking matters.

  • Only one draft TSV can be submitted, with no resubmission, and the returned feedback is assumed to be at least one scalar.

Limitations

  • M3's training-data provenance is undisclosed; neither contamination nor cleanliness was established, and its holdout number was still pending at the time of analysis.

  • The wild-domain weight $\lambda$ of the test set is unmeasured, and the stack-versus-rankmean recommendation flips at $\lambda=0.319$.

  • The sponsor's actual grading polarity and cost constants remain unconfirmed; both scenarios are live.

  • stack_nonlj's inner-fold number is in-sample and unusable, so its selection rests on only two honest estimates.

  • The holdout cannot resolve differences smaller than about 5–6 false alarms, so its rule ordering is near the noise floor.

  • No expert could quantify the expected gain from adding wild bona fide data in a frozen-embedding setup; published figures come from full in-domain training.

  • The codec hypothesis for the 7.2 kHz edge is untested.

  • Several externally cited figures (RawBoost's mechanism, VoxCeleb access friction, the SAMO clustering result, In-the-Wild degradation magnitudes) did not verify against sources and are carried as reported-but-unverified; one expert's ASVspoof 5 constant and UR-AIR augmentation figures graded as incorrect and were dropped.

Technical Detail

The scoreboard arithmetic that frames everything

Points are $(1-\mathrm{ours})/(1-\mathrm{best})\times 60$. If the best team lands near 0.05, the slope is

\frac{d(\text{points})}{d(\mathrm{minDCF})} = -\frac{60}{1-0.05} \approx -63\ \text{points per unit DCF},

so the entire spread between an excellent 0.05 submission and a mediocre 0.15 one is about 6 points out of 100. The rankmean-versus-stack decision is worth roughly 2 points on the holdout axis and 4 on the ITW axis. Getting the score direction wrong costs essentially all 60 minDCF points, because a good detector submitted with the wrong polarity lands at the trivial-system ceiling of 1.00 — which is exactly what the team already observed when running their own scores through the shipped package unmodified. That asymmetry — a ~2-point question versus a ~57-point question versus a 40-point README-and-diversity question — is the single most important reframing either expert produced, and it should drive lane allocation for the rest of the day.

On the test set ($\approx$1,170 real / 501 spoof, matching the 0.3 prior), one false alarm costs 0.0080 DCF and one miss 0.0020 DCF — exactly the stated 4:1. On the holdout (1,858 real / 2,000 spoof), one false alarm is 0.0050 DCF and one miss 0.00050 DCF. These per-file conversions are what make the rest of the analysis tractable.

Item 1 — Selection under disagreement

The disagreement as originally framed (inner OOF 0.250 vs 0.258; holdout 0.146 vs 0.066) is stale: those are pre-band-fix M1 plus handcrafted v1 numbers on a different row set. On the v3/v4 rows in the fusion v0 table, inner OOF orders rankmean 0.254 < zmean 0.259 < M1b v3 0.301 and the holdout orders 0.015 < 0.018 < 0.072. Inner and holdout now agree that fusing beats M1b alone. The live disagreement is between the NSA domain (inner + holdout, both say fuse) and In-the-Wild (says don't). That is a domain-weighting question, not a statistical-selection question, and no resampling machinery answers it.

The mechanism is separable. Fusion with handcrafted v4 (a) suppresses false alarms by requiring agreement on real speech — holdout LibriSpeech-real 0.102 → 0.015, ITW real $P_{FA}$ 0.8% → 0.15% — and (b) softens spoof scores, ITW $P_{miss}$ 27.8% → 59.5%. Effect (a) replicates across domains; effect (b) is pure damage on out-of-family spoofs, because handcrafted v4 has ITW $\mathrm{AUC}=0.76$ but $P_{miss}=97\%$ — ranking signal with no usable operating point. Under $W=9.333$ the ITW trade is a false-alarm gain of $9.333\times0.0065=0.061$ against a miss loss of 0.317, net −0.256, which is why ITW minDCF moves 0.342 → 0.379. Gemini's fold-composition explanation completes the picture: handcrafted v4's inner-OOF failures are grad_tts and pro_diff (both 1.00), and neither generator is in the 2-generator holdout, so the holdout is a favourable draw for it.

The holdout is also at its resolution floor. The rankmean-versus-stack gap of 0.029 DCF is about 5.8 false alarms or 58 misses; the rankmean-versus-zmean gap of 0.003 is 0.6 files. At three observed false alarms the 95% Poisson interval spans roughly 0.6 to 8.8 files. Meanwhile the ITW $P_{miss}$ gap is ~317 files against a binomial SD near 16. This is precisely the regime Cawley and Talbot warn about: selection-criterion over-fitting produces effects comparable in size to the true differences between candidates [S19], and their prescribed remedy for a high-variance selection criterion is a larger validation sample [S19] — which In-the-Wild is.

Run the ten-minute decomposition first: for each rule, print the argmin threshold on the holdout and the raw $(\#FA, \#miss)$ counts there. This is reading a breakdown of a number already computed, not selecting on the holdout. If rankmean's advantage is mostly false-alarm-count-driven, the two are tied on the holdout and the choice falls to ITW.

On the proposed machinery: rank averaging is already a candidate rather than a fix; per-fold weight stability adds nothing when the instability source is already known; nested CV is correct in principle but its outer loop still contains only the eight in-family generators, so it buys a better estimate of the wrong quantity; the constrained stacker is worth doing, but as a one-parameter $\alpha$-sweep that costs twenty minutes rather than a full nested framework.

Item 2 — Draft-review usage

Using the one shot to discriminate between fusion candidates is unsound: a single scalar reports the test minDCF of the one ranking you sent and says nothing about the counterfactual, and the question is worth 2–4 points against 12–30 points in expectation for the direction read. Both experts agree the shot goes to direction.

They split on payload. Gemini wants M1b v3 alone as a clean, well-understood baseline; Claude wants the actual shipped artifact, complete with gating, the pinned block, tie-jitter and exact TSV formatting. Claude's argument wins on breadth of return: one number then yields direction, the true test minDCF of the ranking you will actually ship, a read on how badly the holdout over-states performance, and format/parse validation — a malformed TSV is a silent zero with no second chance. The direction read survives either payload because the two hypotheses sit an order of magnitude apart, so there is no interpretive cost to sending the real artifact.

Item 3 — The fusion rule at 14:00

On the two honest estimates, zmean (0.018, 0.387) is dominated by rankmean (0.015, 0.379) on both axes and should be dropped; M1b v3 (0.072, 0.342) is dominated by stack_nonlj (0.044, 0.317) on both axes, leaving a Pareto frontier of {rankmean, stack_nonlj} with M1b retained as the panic fallback. Between the frontier pair, stack_nonlj wins on minimax regret (0.029 vs 0.062), wins on the better-powered axis, and is the only one that survives the inverted cost structure — rankmean's entire edge is an FA-minimisation strategy tuned to $W=9.333$, and if the grader weights spoof-accepted at $4\times$, a 59.5% ITW $P_{miss}$ becomes the expensive error. Claude's re-ranking under the inverted weights puts M1b at 0.310 and stack at 0.344 against rankmean at 0.601 and zmean at 0.591, so the M1b-dominant family is robust in both worlds and the equal-weight family is not.

The pre-declared swap rule: estimate $\hat\lambda$, the wild-domain weight of the test set, from label-free channel statistics (95% spectral rolloff, long-term tilt, noise-floor level and stationarity, a reverberation proxy), train a tiny domain classifier to separate holdout-real from ITW-real, and average its predicted P(wild) over the 1,671 test files. The crossover is $\lambda=0.319$: below it rankmean wins, above it stack wins. Claude's falsifiable prior is that a uniform 7.2 kHz wall on every file suggests a single curated re-encode pipeline rather than genuine heterogeneous field audio — real telephony would show a 3.4 kHz mode. This is the cheapest decision-relevant measurement left.

Is the rising test share a warning sign? No — it is a category error. $\mathrm{minDCF}$ is a minimum over a threshold sweep and depends only on the ranking. Any monotone transform — the 0.5 cut, z-scoring, T-norm, Platt scaling, test-ECDF ranking — changes the share above 0.5 and changes minDCF by exactly zero. Gemini reached the same verdict by a different route (threshold flattening), but Claude's framing is the operative one: score normalisation to "fix" the share is worth exactly zero points, and the ITW $P_{FA}$-at-inner-threshold figures are likewise calibration statistics the grader will never compute. The relevant Bayes threshold, if one is ever needed, is $W/(1+W)=0.903$ under the brief and 0.800 under the shipped code — not 0.5.

The share retains one legitimate diagnostic use: fit the observed test-score CDF as a two-component mixture of the inner-OOF class-conditional CDFs and estimate $\hat\pi$. A value near 0.30 is consistent with the prior; near 0.45 indicates the real-side distribution has shifted upward, which is genuine FA inflation. $\hat\pi$ is itself biased under class-conditional shift, so treat it as a smoke alarm, not a selection metric.

Rules worth A/B-ing this morning, all cheap in the existing script: the $\alpha$-sweep in rank domain $(1-\alpha)r_{M1b}+\alpha r_{HC}$ over $\alpha\in\{0,0.1,\ldots,0.5\}$ (highest EV — the FA benefit saturates fast while the $P_{miss}$ damage grows roughly linearly, so expect an optimum near $\alpha\approx0.2\text{–}0.3$); the same sweep in z domain; the min-rule and max-rule as the maximally FA-averse and miss-averse bounds; a cascade veto that uses $r_{M1b}$ everywhere except an ambiguous mid-band where it averages in the handcrafted rank; median-of-three including M3; a capped weighted mean; a non-negative stacker shrunk toward equal weights; and a tie-jitter wrapper. Report every rule on inner OOF, holdout, per-real-source, ITW under both cost weightings, and $\hat\pi$. Pre-declare the selection objective before looking, cap the menu, and do not iterate — selection over ten rules on a proxy set is exactly the over-fitting risk Cawley and Talbot quantify [S19].

Item 4 — Weighting M3 under possible contamination

The structural fact both experts converge on: LJ Speech, LibriSpeech, DiffSSD and In-the-Wild are all public, as are the holdout's two generators and 26 bona fide groups. There is therefore no guaranteed-clean evaluation set for M3 anywhere in the team's possession — "calibrate on the holdout only" moves the contamination one level up rather than containing it. The only guaranteed-unseen data is the 1,671 unlabelled test files.

Note also that near-perfect separation on a development split is weak evidence of generalisation even with strictly disjoint protocols: in-domain AASIST scores 0.61% EER and 0.0160 minDCF on SpoofCeleb's validation split but 2.37% and 0.0328 on its evaluation split [S5]. So $\mathrm{AUC}=1.0$ on eight generators is not by itself proof of leakage — Gemini's word "guarantees" is too strong — but combined with undisclosed training data and universally public evaluation sets, it is not evidence of strength either. Treat it as uninformative.

The policy follows: never let a fitted stacker see M3. Admit it only as a capped vote in an unfitted rank rule (median-of-three, or weight 0.25) and only if the 06:00 holdout number lands below 0.05; exclude entirely if holdout exceeds 0.10, which would mean neither leaked nor strong. Gemini's confidence-gate variant is the same idea implemented as routing: defer to M3 only on extreme scores. Claude adds an important refinement — restrict M3 to FA suppression, damping scores where M1b says synthetic but M3 says strongly bona fide, and never allowing it to promote a file toward synthetic. The rationale is that M3's most useful claim (0 of 2,000 ITW false alarms) is on the real side, and memorising real speech is far less dangerous than memorising spoof generators.

Three cheap leakage probes, roughly an hour total. First and best: perturbation sensitivity — take 500 inner clips, apply label-preserving perturbations (low-bitrate MP3 round-trip, +20 dB SNR noise, ±2% time-stretch, one-sample circular shift), re-score with both M3 and M1b, and compare $\Delta\mathrm{AUC}$; a model that memorised specific files degrades far more under tiny perturbations than one that learned generalisable artifacts. Second: Spearman $\rho(r_{M1b},r_{M3})$ on the holdout versus on the test set — a large drop is direct evidence that holdout agreement is memorisation-driven, and it uses no labels. Third: score the MLAAD spoof already on disk; near-perfect on classic public sets but mediocre on MLAAD is consistent with memorisation. Spend ten minutes grepping the model card and repo for a training-data list, then stop.

Item 5 — Default answer and game theory

For a block of mass $u$ with internal spoof rate $q$, placing it at the bottom of the submitted ranking costs $uq/\pi_{synth}$ and at the top costs $Wu(1-q)/(1-\pi_{synth})$, giving

q^{*}=\frac{W/0.7}{1/0.3+W/0.7}.

Under the brief, $W=9.333$ gives $q^{*}=0.800$: pin to the minimum if $q<0.800$. Under the shipped code's inverted semantics, $q^{*}=0.0968$: pin to the minimum if $q>0.0968$. The indeterminate files sit at $q\approx0.30$, comfortably inside $[0.097,0.800]$ with roughly 3× margin on both sides. So "push uncertain files to the real end" is genuinely optimal, not a vibe — and it is the only hedge that holds under both score conventions. Gemini's independent all-real (0.3) versus all-spoof (2.8) check confirms the direction of the asymmetry under the brief.

Implementation is about placement, not value. Map determinate scores into $[0.001,1.000]$; put the indeterminate block in $[0.000,0.001)$, strictly below everything. Do not emit a constant — order within the block by whatever weak signal remains (raw M1b score, voiced fraction, duration) and use a deterministic hash jitter for genuinely signal-free files. Because minDCF is a minimum over available thresholds, distinct values offer the evaluator a superset of cut points and can only weakly improve the score; the expected gain is on the order of 0.001–0.002 DCF but is never negative. Placing the block in the middle is weakly dominated: it constrains the sweep without buying anything.

Category policy: decode failures and non-speech go to the bottom of the block. High-disagreement files should not be collapsed into the block — they carry noisy but real ranking information, so compress them toward the low end of the determinate range instead, which the $\alpha$-fusion and the cascade veto already do. Low-confidence files near the middle stay where they are; do not manufacture certainty.

If the shipped code is used, the block policy is unchanged but the determinate ranking must be flipped, and rule selection should shift to the miss-averse criterion. No hedge protects the ranking of the determinate files — a ranking and its reverse cannot both separate — so the draft review really is the only protection there. That is the correct, narrower version of Gemini's claim.

Item 6 — Channel robustness

The ITW gap is a domain problem, and the literature is consistent about the cause: existing corpora are dominated by clean read speech because TTS and VC training requires studio-quality audio [S5] — which describes LJ plus LibriSpeech plus VCTK exactly. The in-domain versus cross-domain AASIST spread on SpoofCeleb (0.61%/0.0160 validation vs 2.37%/0.0328 evaluation) [S5] is the mild version of this; the In-the-Wild study reports far larger degradations for benchmark-tuned systems [S18] (reported but not independently verified here).

The experts split on the lever. Gemini recommends RawBoost, which operates directly on raw waveforms to model telephony encoding, transmission and convolutive noise without requiring external data [S15] (reported but not independently verified). Claude recommends adding wild, non-read bona fide clips to the frozen-embedding path first. Two pieces of evidence favour Claude's ordering. First, the team's own post-band-fix numbers show that adding VCTK real speech did help on both axes once the 7.2 kHz confound was removed, so the diversity hypothesis is alive. Second, aggressive augmentation is documented to hurt SSL front-ends specifically: Fraunhofer SIT found extensive augmentation improved a non-SSL front-end but degraded an SSL one, and with wav2vec2-large, band-stop, parametric-EQ and tanh-distortion augmentation worsened minDCF in every configuration tested (0.066→0.081; 0.063→0.074; 0.097→0.144) [S16]. M1/M1b is a frozen XLS-R front-end from the same family. The same work found that adding a second corpus gave a marginal gain without augmentation (0.066→0.063) and a larger one with it (0.081→0.074), while piling on all available data was worse than the two-corpus setting [S16] — so add one good corpus, not three.

Concretely, the frozen path makes corpus addition nearly free: extract XLS-R layer-7 embeddings for ~4k new real clips (roughly 10 minutes at the measured 40-minutes-per-20k rate), speaker-group them into inner folds only, refit the logistic regression in seconds, and re-score holdout, ITW and test. Corpus choice should prioritise non-read, channel-diverse speech. SpoofCeleb is designed so that its bona fide speech is real-world noisy speech [S5][S14], with the authors' own caveat that the bona fide was enhanced and enhancement artifacts may confuse detector training [S5][S14]. VoxCeleb is the obvious alternative but its audio requires a request form and password [S20] (reported but not independently verified), a real same-day logistics risk — if nothing downloads cleanly within 30 minutes, abandon and fall back to augmentation rather than burning the morning.

Claude's untested hypothesis deserves a slot: a uniform ~7.2 kHz wall on every 16 kHz file is more characteristic of a low-bitrate codec round-trip than of naturally band-limited field audio, and a Kaiser low-pass matches the cutoff but not the quantisation noise, pre-echo, or psychoacoustic residue. If the test went through a codec and the training data did not, codec artifacts on real test speech can masquerade as vocoder artifacts — a clean mechanistic explanation for FA inflation. The test is cheap: encode 50 LJ clips at several bitrates, decode, compare rolloff slope and high-band spectral flatness against the test files, pick the closest match, apply the round-trip to all training clips, re-extract and refit. Apply it to both classes symmetrically — augmenting only the real class would teach "codec artifact implies real", the 7.2 kHz shortcut running in reverse. Keep the band-matching low-pass and avoid aggressive high-pass augmentation, since foundation-model front-ends are relatively robust to low-pass filtering but degrade sharply under high-pass [S6].

On the unlabelled test set: per-file z-norm and channel-statistic extraction are safe; the mixture-proportion $\hat\pi$ diagnostic is safe with the bias caveat; unsupervised CORAL or mean-shift on test embeddings is permitted but risky (a global affine match of a 30/70 mixture can shrink the class-discriminative direction) and should be validated train-to-ITW first and only shipped if it helps there; score normalisation to the test ECDF is safe but pointless because it is monotone. Both experts flag nearest-neighbour-to-LJ as a trap, and Claude gives the sharper reason: four of the ten DiffSSD generators are LJ-voice TTS that clone LJ's speaker, so LJ-proximity is a spoof-cluster indicator at least as much as a real-file indicator. Use it only to describe speaker composition in the README, never in the score path.

One-class and centre-loss objectives remain contraindicated. SAMO's authors report that bona fide speech from different speakers naturally forms multiple clusters in embedding space and that compacting them into one caused misclassification [S4] (reported but not independently verified). With one LJ speaker and ~80 LibriSpeech readers, the bona fide manifold is exactly the narrow multi-cluster case these objectives fail on.

Inference-time speech enhancement is documented to give measurable gains under noise and MP3 corruption [S6], but it adds a model to a CPU Docker image that is still unowned. Skip it today.

Item 7 — The non-speech gate

This is the best points-per-minute action available and both experts identify it, though only Claude sizes it. Silence currently scores 0.9996 and a synthetic music chord scores 1.0 — confidently wrong at the top of the ranking. On the test set, five such real files at the top add 0.040 DCF (~2.5 points), ten add 0.080 (~5 points), twenty add 0.160 (~10 points). The downside of gating a genuinely synthetic non-speech file to the bottom is 0.0020 DCF each — a 4:1 asymmetry in favour of gating. Against a fusion decision worth ~2 points, this is not close.

Procedure, about 30 minutes of CPU: run the existing VAD over all 1,671 test files and compute voiced fraction $v$ and total voiced duration $d$; plot the histogram (a measurement, not a labelling decision). Gate on $v<0.20$ or $d<0.5$ s or decode failure, routing the file into the pinned block at the minimum score. Add a cheap music guard — spectral flatness, harmonic-percussive ratio, and $f_0$ stability, with a sustained-chord signature (stable multi-$f_0$, near-zero formant movement) also routed to the block. Calibrate the threshold on training bona fide only, targeting under 0.5% trip rate on LJ and LibriSpeech, never on the test set. Log every gated file for the README. If the histogram shows zero files below threshold, the cost is 30 minutes and the return is a documented negative result that earns rubric credit.

Item 8 — Diversity and agentic orchestration

At 20% of the grade this is worth more than every remaining minDCF improvement combined, and the README is another 20%. Both experts agree the zero-signal engineered detectors should be documented honestly rather than fused. Keep them in the repo and in the orchestrator's routing trace but out of the score path: the rubric itemises container/metadata, ENF and splice explicitly, the README rubric rewards "what did not work", and a zero-AUC feature in a fused score adds variance for nothing. Document each null result with its mechanism — uniform FFmpeg decode destroys container evidence, 16 kHz mono PCM puts ENF's 50/60 Hz below the useful band after preprocessing, and re-encoding destroys splice discontinuities.

Replacements that survive a uniform decode, roughly in expected-signal order: noise-floor stationarity (real field audio has non-stationary background, TTS does not — and this doubles as a channel feature for $\hat\lambda$); speaker-embedding drift within a clip (cosine distance between first-half and second-half embeddings, a splice proxy); breath and pause statistics, since neural TTS under-generates breaths; microprosody ($f_0$ jitter, shimmer, contour high-frequency energy), since diffusion TTS over-smooths; phase and group-delay features, which the current magnitude-only handcrafted set omits entirely; and a Griffin-Lim round-trip distance, which is cheap and novel enough to anchor the explainability section.

For orchestration credit beyond static rules, a judge wants evidence that per-file routing changed the decision and that the delta was measured. Build a router that reads measured file properties (voiced fraction, duration, estimated SNR, effective bandwidth, speaker count) and selects the analysis chain: non-speech to the gate; short clips skip prosody and pause statistics for insufficient support; low-SNR or wild-channel files up-weight the SSL path and down-weight the magnitude-spectral detector; multi-speaker files trigger splice and drift analysis. Add an explicit abstention path into the default policy, emit a per-file JSON trace with each analysis's contribution, ship 5–10 worked examples, and report a router-on versus router-off ablation on holdout and ITW. Reporting a measured null delta is itself rubric-positive — the SZU-AFS team's published finding that fusion sometimes lands between the individuals with no improvement, so that using only the best classifier was sufficient [S17], is the model for that kind of honest negative result.
