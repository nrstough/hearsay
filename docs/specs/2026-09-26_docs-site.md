## Problem

The documentation is about 80 markdown files (README, `CLAUDE.md`, the plan, architecture, status, code map and NSA brief, 27 reports and plan reviews, 11 run specs and audits, 15 handoffs, 7 consult records, ten working-method skills and two review rubrics). ## Design decisions

- **D1 (generator).** `scripts/build_site.py`, Python standard library only (plus `hearsay.metrics`, importable through `uv run`, for the cost constants). Inputs: the markdown corpus (`README.md`, `CLAUDE.md`, `docs/**/*.md`, `.claude/**/*.md`), the hand-written page sources under `docs/site/source/` (HTML fragments for story and spec pages, `glossary.json`, Mermaid sources, the stylesheet and scripts), and git (for per-file commit hashes). Output: `docs/site/*.html`, `docs/site/library/**/*.html`, `docs/site/specs/*.html`, `docs/site/img/**`, `docs/site/search-index.js`, `docs/site/site.css`, `docs/site/site.js`. Modes: build (default), `--check` (rebuild into a temporary directory and diff against the committed output; non-zero on any difference), `--check-citations` (D8), `--strict` (a missing diagram render or an unresolvable link is an error rather than a warning). Sources live inside `docs/site/source/` so this lane owns exactly `docs/site/` plus the script and its test; the directory name has no leading underscore (Jekyll drops those) and matches no `.gitignore` pattern.
- **D2 (converter).** A markdown-to-HTML converter written for this corpus: ATX headings with GitHub-style slugs (lowercase, punctuation stripped except hyphens, spaces and underscores, spaces to hyphens, duplicates suffixed `-1`, `-2`), paragraphs, ordered and unordered lists with nesting, tables (alignment row, escaped pipes, pipes inside code spans), fenced code blocks (any language tag, verbatim and escaped), inline code, `**bold**`, `*italic*` and `_italic_` with an intra-word underscore guard, links, images, blockquotes, horizontal rules, hard line breaks, and raw HTML from an allowlist of tags the corpus already uses (everything else escaped). Mermaid fences become diagram embeds (D4). Unknown constructs render as escaped text, never dropped.
- **D3 (links).** Links between markdown files become links between site pages (fragments preserved through the same slug rule). Links to code, scripts, tests, docker, splits, `.claude/`, and to gitignored paths (`models/`, `outputs/`, `data/`, `weights/`, `submissions/*.tsv`) become GitHub blob links (`https://github.com/nrstough/hearsay/blob/main/<path>`). `http`, `https` and `mailto` links are untouched. Images referenced by any rendered document are copied under `docs/site/img/` and the `src` rewritten. A link whose target exists nowhere is reported; under `--strict` it fails the build. All site links are relative and name an explicit `.html` file, never a directory, so they resolve identically under `file://`, `http.server` and Pages.
- **D4 (diagrams).** Every Mermaid block (the five in `docs/architecture.md`, and the site's own: pipeline, router tree, fusion arithmetic on one worked file, fold scheme, score line with the pinned block, decision timeline, the cost picture) is pre-rendered to two SVGs, light and dark, named by the SHA-256 of the block's text, under `docs/site/img/mermaid/`. Rendering is done once with Mermaid 11 (fetched from the npm registry into the scratchpad) under Node Playwright and the pre-installed Chromium, by a small script committed as `docs/site/source/render-diagrams.mjs` for re-rendering on the Mac; the SVGs are post-processed to stable element ids so the build stays deterministic. The generator embeds the pair with a CSS-driven light/dark swap that follows both `prefers-color-scheme` and the site's manual theme toggle. If a block has no rendered pair, the generator emits the Mermaid source with the jsDelivr script tag as a fallback and warns; `--strict` makes that an error, and the committed site must contain no such fallback. The committed `docs/img/architecture-flow.svg` is reused for the main flow in the library; the story's own pipeline diagram is redrawn to the shipped rule.
- **D5 (footer and commit).** Every page's footer names its source file(s) and each file's last commit (`git log -1 --format=%h -- <file>`), plus the sentence "the markdown is the record". The About page states the newest source commit. HEAD is never written into a page, so the output is stable until a source changes. If git is unavailable the footer says "commit unknown" and `--check` is skipped by the test.
- **D6 (tooltips and glossary).** `docs/site/source/glossary.json` holds each term once (term, definition, optional aliases). Story, spec and glossary pages mark terms with a template tag (`{{term:minDCF}}`) that the generator expands to `<span class="term" tabindex="0" role="note" aria-describedby="…">` with a hidden definition element; CSS shows it on `:hover` and `:focus-within` (which also covers tap on touch devices), positioned to stay inside the viewport on phones. Terms are never inserted inside `<a>`, `<code>` or `<pre>`; the generator refuses. Library pages get no automatic tooltips (rendered markdown is left as written).
- **D7 (search).** `docs/site/search-index.js` assigns one global array of `{title, section, url, text}` records for every page; `site.js` does a case-insensitive substring scan and lists matching pages with a snippet. It is a script, not fetched JSON, because `fetch` of a sibling file fails under `file://`. Each section index is a plain HTML list, so nothing depends on JavaScript.
- **D8 (citations).** Every figure on a story or spec page is written as `{{num:0.0065|README.md#numbers}}`, expanded to `<span class="num" data-src="README.md#numbers">0.0065</span>` followed by a small source link (GitHub blob URL plus the local path as its title). `--check-citations` finds the literal number string in the named file, scoped to the named section when a fragment is given, and fails on any miss; it also scans story and spec pages for decimal or percentage numbers outside citation markup, code, and a fixed allowlist (dates, times, version strings, section numbers) and fails on any uncited one. Spec pages may cite code (`src/hearsay/metrics.py#L29`), in which case the check reads that file and verifies the number appears on or near that line.
- **D9 (cost function element).** The constants come from `hearsay.metrics` at build time (`C_FA`, `C_MISS`, `PI_SYNTH`) and the derived weight `C_FA·(1−π) / min(C_FA·(1−π), C_MISS·π)` is computed the same way `metrics._default_cost` normalizes. Home carries a designed panel with the formula and the "one false alarm costs as much as 9.33 misses" statement; the metric page carries the derivation, a diagram of the cost picture, an interactive with two sliders (P_FA, P_miss) that evaluates the normalized cost with the same constants, the operating-threshold explanation (Bayes threshold on the LLR from `bayes_llr_threshold`), the sponsor-code reading (π 0.5, 4× on a missed fake, higher = bona fide, from `sponsor_min_dcf`), and the pinned-block table (consult item 5). No measured curve is drawn; the element is the formula only.
- **D10 (determinism).** Directory walks are sorted; no timestamps; all files written with `encoding="utf-8"` and `\n`; the search index is emitted in sorted page order; Mermaid SVG ids are rewritten to a prefix derived from the content hash. Building twice yields identical bytes.
- **D11 (design).** Tokens on `:root`: navy `#00254b`, blue `#005493`, gold `#c37530`, amber `#ffb800`, a pale canvas; a dark theme under `prefers-color-scheme: dark` and under `[data-theme="dark"]` with a toggle that stores the choice in `localStorage` (wrapped in try/catch). System sans-serif stack, a monospace stack for evidence lines, routing logs and TSV excerpts. One type scale. Phone width first: 16 px gutters, no horizontal scroll at 390 px, the left nav collapses to a top menu. No webfont files are copied (Satoshi and Doto are Fontshare-licensed; Aileron is not needed).
- **D12 (content rules).** Plain English in the README's voice. The README wins over any other document on a number. The story's diagrams show the shipped rule as the README states it. Spec pages state a parameter only with a citation to the code file and line or the document that sets it; a parameter neither states is "not stated". NSA's returned draft minDCF is a labelled blank until it exists.
- **D13 (library).** Every markdown document is rendered once, in its folder group, with its title from the first heading, its source path and commit in the footer, and internal links rewritten (D3). Historical documents (`docs/scoping.md`, `docs/master-doc.md`) render as they are, banner included. The skills and rubrics render under "Working method".
- **D14 (ownership and hygiene).** This lane creates `docs/site/**`, `scripts/build_site.py`, `tests/test_build_site.py`, this spec, `docs/reports/2026-09-26_docs-site-plan.md` and `docs/reports/2026-09-26_docs-site.md`, and touches nothing else. Staging is by explicit path, never `git add -A`. The site contains no audio file and no path matching a `.gitignore` pattern (`build/`, `dist/`, `*.log`, `outputs/`, `models/`, `data/`).

## Acceptance criteria

3. The handoff's link check (`cd docs/site && uv run python -c "…"`) prints `links OK`.
4. `uv run pytest -q` keeps every previously passing test passing (baseline recorded at execution start); `uv run ruff check .` is clean; `tests/test_docs_consistency.py` unchanged from baseline.
5. Playwright pass (scratchpad, Node, not part of pytest): every page opened from `file://` at 390 px and 1280 px in light and dark; `scrollWidth ≤ innerWidth` on every page; screenshot count = pages × 4; recorded here.
6. Content: all eight story pages plus the Glossary; every spec page in the P1 list; every markdown document in the library; the About page; every Home-page number from the handoff (shipped rule inner 0.135 / holdout 0.0065 / In-the-Wild 0.228 brief and 0.239 sponsor-code; previous rule 0.140 / 0.014 / 0.260 / 0.267; M1b v3 0.301 / 0.072 / 0.343; Spectra In-the-Wild 0.065; test share above 0.5 27.4% from the README's Numbers table and 27.5% from the ablation table, each cited to its own table; 1,671 files; 0 gated; router on vs off holdout 0.0065 vs 0.0200 and In-the-Wild 0.229 vs 0.274) present and cited; NSA's draft minDCF shown as pending.

## Failure modes → tests (`tests/test_build_site.py`, hermetic, standard library + pytest)

| Stage | Failure mode | Test |
|---|---|---|
| Converter | heading levels or anchors wrong; duplicate headings collide; links to `README.md#numbers` miss | slugs for levels 1–6, duplicates `-1`/`-2`; a link fragment resolves to the emitted id (counterfactual: changing the slug rule breaks it) |
| Converter | nested or mixed lists flatten | ordered inside unordered, three levels, items with code spans and links |
| Converter | tables: alignment row, `\|`, pipes inside code spans, `<br/>` in cells, missing trailing pipe | one test per case; the README's Numbers table as a fixture renders with equal column counts in every row |
| Converter | a `#` or `|` line inside a fence treated as markdown; fence contents unescaped | fence contents verbatim and escaped (counterfactual) |
| Converter | inline: backticks with `<tab>`, `&`, `|`; emphasis styles; intra-word underscores (`nsa_folds.csv`) italicized; Unicode (`·`, `×`, `λ̂`, `±`, `→`) mangled | intra-word guard (counterfactual); escaping of `<`, `>`, `&`; UTF-8 round-trip |
| Converter | blockquotes, rules, images, bare URLs, `\*` escapes, raw HTML (`<sub>`, `<br/>`) | one test each; a non-allowlisted tag is escaped (counterfactual) |
| Converter | paragraph merging, hard breaks, list after paragraph | boundary tests |
| Converter | some corpus file renders wrong | every `*.md` in the corpus converts; output tag-balanced (stack checker with void elements); no leftover `**`; no line starting with `|` or `#` outside `<pre>`; no unescaped `<` outside tags |
| Links | `.md` link not rewritten; `../CLAUDE.md` from a nested doc; fragment lost | rewrite tests for each form |
