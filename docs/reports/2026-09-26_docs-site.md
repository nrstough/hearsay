## What it is

A self-contained HTML site under `docs/site/`, generated by `scripts/build_site.py` (Python standard library only) with its output committed, so nothing needs building to read it. It works opened from a checkout (`docs/site/index.html`), from `python3 -m http.server` in `docs/site`, and as a GitHub Pages site from `main` / `docs` once the repository is public. There is no runtime dependency: no CDN, no webfont, no library. Every number on a hand-written page carries a source link to the file and section it came from, and the build refuses a number it cannot find there.

The link check that passes as written:

```bash
cd docs/site && uv run python -c "
import re, pathlib
bad = []
for p in pathlib.Path('.').rglob('*.html'):
    if p.parts[0] == 'source': continue
    t = re.sub(r'<(pre|code)\b.*?</\1>', '', p.read_text(encoding='utf-8'), flags=re.S)
    for h in re.findall(r'href=\"(?!https?:|mailto:|data:)([^\"#]+)\"', t):
        if not (p.parent / h).exists(): bad.append((str(p), h))
print('links OK' if not bad else bad)
"
```

## Deviations from the plan, and why

- Page metadata lives in a JSON comment at the top of each fragment instead of a separate `pages.json`; one place per page, same information.
- The decision timeline is an HTML list with a source link per event, not a Mermaid diagram: more legible on a phone, and every time is cited.
- The cost explorer's sliders and the inverted-index search were on the cut list; both were built.
- All 26 spec pages were written; none was cut. The one page the plan listed as "explanation-json" and "runner-routing" are two pages, as planned; the spec index counts 27 because it includes itself.
- A `docs/.nojekyll` file was proposed at the plan stop and not created: the site does not need it, and the file lies outside this lane's directory.
- The plan's verbatim link-check one-liner (B4) exits 1 on the site: the regex's own text is rendered inside `<code>` on the plan's and the spec's library pages. The criterion is met by the command above, which drops `<pre>` and `<code>` contents first, and by the test, which does the same.
- The "no git hash and no HEAD in any page" assertion (B14) holds for page footers only: library pages legitimately quote commit hashes and "HEAD" (the README, the reports, the plan-review skill).
- The `node -e` check of the cost expression (B16) was not done; the expression is evaluated in Python on 24 (P_FA, P_miss) pairs against `metrics.cost_at`.
- B3's "gitignored citation target renders as `<code>`, never a link" was first implemented as a build error; the audit round implemented it as specified, with a warning and a test.
- Found by the audit round and fixed in the same commit: the uncited-number scanner exempted a number followed by `.` or `,` (11 numbers on the committed site were uncited; all had sources and are now cited); the export-page exclusion from the body index never fired (it keyed on rendered text length rather than source size); the `--check` counterfactual test did not run the comparison; markdown image and link syntax could reach an external image or a `javascript:` target (raw HTML could not); three `audio.py` line ranges were off by three. Round 2 added: a gitignored citation target that exists on the machine became a GitHub link (the Mac would have shown dead links and `--check` would have diverged); protocol-relative URLs and raw `data:text/html` images passed the guards; scientific-notation numbers were not scanned.
