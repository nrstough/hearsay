## Design amendments from the exploration (override the run spec where they differ)

- **A1 (D5 replaced).** No git data in any page. Each page's footer names its source file(s) and the first 12 hex characters of the SHA-256 of each source's bytes ("content `1a2b3c4d5e6f`"); the About page explains that `git log -S` or the report maps a content hash to a commit, and the report records the commit. Reason: a source edited in the same commit as the site cannot carry that commit's hash, so `--check` would fail forever; and tests need no git.
- **A2 (D4 amended).** Rendering is a separate Node script, `docs/site/source/render-diagrams.js` (CommonJS; `require(process.env.PLAYWRIGHT_MODULE || "playwright")`; Mermaid path by argument), run here once. It renders every `.mmd` under `docs/site/source/diagrams/` (the site's own diagrams, plus the fenced blocks that `build_site.py --extract-mermaid` writes to `docs/site/source/diagrams/from-docs/<sha12>.mmd`) in a fresh browser context per diagram and theme with `mermaid.initialize({startOnLoad:false, theme, securityLevel:"strict", htmlLabels:false, flowchart:{htmlLabels:false}})`, render id `mmd-<sha12>-<theme>`, after `document.fonts.ready`; it fails on any page error or an SVG containing `error-text`. Post-processing: XML prolog; `width`/`height` set from the `viewBox`; `width="100%"` and the inline `max-width` style dropped. Output: `docs/site/img/diagrams/<name>-light.svg`, `<name>-dark.svg`, and `docs/site/img/diagrams/manifest.json` = `{name: {"sha256": <source hash>, "mermaid": "11.17.2", "chromium": <version>}}`. **`--check` verifies each Mermaid source's hash against the manifest and the presence of both SVGs; it does not compare SVG bytes** (they depend on the rendering machine's fonts). The dark/light swap is two `<img>` elements with `width`/`height` attributes and CSS display rules keyed on `prefers-color-scheme` and `:root[data-theme]` (the risk agent's verified rules), never `<picture>` (cannot follow the toggle) and never `<object>`.
- **A3 (D7 amended).** The search index is a prebuilt inverted index: `window.HEARSAY_INDEX = {pages: [{u, t, s, h}], terms: {"mindcf": [3, 17, …]}}` with tokens `[a-z0-9_]{3,30}` from headings and body text (fenced code excluded), page ids as small integers, terms sorted, JSON with `sort_keys`. Query = AND of prefix-matched terms (binary search over the sorted term list), ranked by title and heading hits; results list the page with its section, no snippets. Measured on the corpus: about 0.5 MB.
- **A4 (converter scope fixed by the inventory).** No setext headings (a `---` line is always a rule unless it is a table alignment row); YAML front matter stripped; `__x__` rendered bold as GitHub does; `_` emphasis only with GFM flanking (never opens or closes inside a word); `*`/`_` single emphasis, `**` strong; `\` escapes for `* _ | [ ] # $ < > \`; `$` never special; two-space and backslash hard breaks; task-list items as disabled checkboxes; lazy continuation for blockquotes; code spans joined across a line break by joining paragraph lines before inline parsing; short table rows padded, long rows truncated with a build warning; "``` math" and "``` artifact-content" fences shown as `<pre>`; raw HTML allowlist exactly the export tag set above, with attributes limited to `class`, `style`, `src` (data URIs only), `width`, `height`, `alt`, `colspan`, `rowspan`, everything else escaped, so `<name>` and `<X>` in prose render as text.
- **A5 (layout names).** Flat layout: `docs/site/*.html`, `docs/site/specs/*.html`, `docs/site/library/*.html` (one level, slugged from the source path: `reports-2026-09-26-cpu-detectors.html`), `docs/site/img/diagrams/`, `docs/site/img/`, `docs/site/site.css`, `docs/site/site.js`, `docs/site/search-index.js`, `docs/site/source/**`. No directory or file name from the `.gitignore` collision list; no name starting with `_` or `.`.
- **A6 (tooltips).** The risk agent's verified pattern: `<span class="term" tabindex="0" aria-describedby="tip-N">…<span class="tip-body" role="tooltip" id="tip-N">…</span></span>`; baseline CSS shows the body as a fixed strip at the bottom of the viewport (never clipped at any width); an `@supports (anchor-name: --tip)` enhancement anchors it beside the term on screens wider than 640 px with flip fallbacks; unique ids per page; a two-line Escape handler in `site.js` as progressive enhancement. `.term` is never given `position: relative`.
- **A7 (citations rule, made precise).** The uncited-number scan flags decimals, percentages, thousands-grouped numbers and integers of 100 or more that appear outside `{{num}}` markup, code, headings' section numbers, times (`hh:mm`), dates and version strings. Integers under 100 without a decimal are free (e.g. "ten detectors", "12 layers"). The rule is stated on the About page.
- **A8 (fonts).** System sans-serif and monospace stacks only; no Fontshare files (Satoshi's licence forbids redistribution), no Google Fonts link, no font files at all. `site.css` contains no `http` URL (tested).
- **A9 (build hygiene).** Python 3.11-safe syntax; every directory listing sorted; no `set` iteration into output; `json.dumps(sort_keys=True, ensure_ascii=False, separators=(",", ":"))` with `</script` escaped; files written with `encoding="utf-8", newline="\n"` and one trailing newline; URLs built with `PurePosixPath`; the whole build must finish in under 20 s (tested) to catch quadratic regexes.
- **A10 (Pages).** One empty file `docs/.nojekyll`, outside this lane's directory, proposed to Nathan at the plan stop; the site does not depend on it.

## Risks and mitigations

- **The converter mis-renders one of the three exports.** Mitigation: the corpus smoke test plus reading those pages in the browser; the export path passes allowlisted HTML through and shows math fences as `<pre>`. If a construct still breaks, the page renders the raw block escaped inside `<pre>` rather than dropping it.
- **A number in a story page cannot be traced.** Mitigation: `--check-citations` refuses the build; the number is removed rather than guessed.
- **The README changes tonight.** Mitigation: the Home-page number table is checked against the live README by the test suite; the sync pass re-runs the build and the checks.
- **Diagrams look wrong on a Mac font.** Mitigation: boxes measured with DejaVu Sans are wider than any likely viewer font, so labels have slack; `width`/`height` from the `viewBox` keeps the aspect.
- **Time.** The story pages and the library carry the grade and land at the checkpoint; spec pages follow. If the box runs out during step 9, the finished spec pages ship and the missing ones are listed in the report.
