1. **Critical — The fold policy still violates the required speaker holdout.** Step 7 turns leakage across 41 speakers into an expected test result. Documenting it does not make validation speaker-disjoint, and bootstrapping `group` units does not account for speakers shared across those groups. Use generator-and-speaker-disjoint folds for both validation levels, or explicitly block validation conclusions pending V2-01 and label this run as a diagnostic on the legacy split.

2. **Critical — The primary statistical comparison is undefined.** “Aggregated across layers and pools” does not specify the evaluation basis, stratum weights, treatment of C, or handling of INVALID cells. Comparing each arm against `none` also does not establish whether hardest/easiest outperform the random control. Freeze these choices and include direct paired hardest-minus-random and easiest-minus-random contrasts. Reuse the same group resample across all contributing strata so overlapping pools and layers are not treated as independent evidence.

3. **Critical — Resume can silently mix incompatible experiments.** Cell filenames encode only layer, pool, C and arm; skip-if-exists accepts results after changes to folds, row order, embeddings, mining parameters or implementation. A hash covering the realized arm list is insufficient. Persist and validate input/configuration fingerprints in every checkpoint, write checkpoints atomically, and test stale and truncated files. Derive completeness from the frozen requested grid, not the files found.

4. **Critical — The metadata join is not executable as described.** The embedding manifests already contain `source` and `speaker`; joining those columns from the fold file using the donor’s `DataFrame.join` pattern raises an overlapping-columns error. A merge instead creates suffixed columns, breaking later access. Explicitly reconcile shared columns, validate a one-to-one path mapping, and assert labels and path sets agree before reordering to `inner_path`.

5. **Critical — The replacement shard loader weakens existing integrity checks.** `seen.all()` permits duplicate row indices and silently overwritten embeddings; negative indices also index valid rows. The existing `probe.load_embeddings` checks that row indices form an exact permutation. Preserve that guarantee, validate integer indices, bounds, dimensions and finite values, and test duplicate, negative, missing and non-finite shard data. These should fail R8 before any fitting.

6. **Critical — Mining and confidence readouts lack a defined score scale.** Nested OOF margins come from four different fitted models, yet Step 4 pools their raw values to rank examples. Differences in model scale can determine which fold supplies the “hardest” examples. The spec’s H7 requires scale normalization, but the final plan supplies neither that transformation nor a numerical definition of H5 “confidently wrong.” Freeze both definitions, fit any normalization within the appropriate training folds, and test their intended scale behavior.

7. **Critical — R5 cannot pass for the L7-only arms.** Direction probes and `focal_g2` run only at L7, while every candidate receives a gate requiring three layers including L20. Their failure would be predetermined by missing experiments. Define gate eligibility explicitly: apply R5 to the four-layer primary families and report L7-only arms as descriptive with cross-layer eligibility marked N/A.

8. **Suggestion — The time limit does not cover the declared workflow.** A check between fit cells does not bound queued parallel work, `csweep`, bootstrap, reporting or repeated audits. Use one persisted run deadline, stop scheduling work when it expires, and ensure partial results receive an incomplete report without proceeding through a complete-grid gate.

9. **Suggestion — Restore a semantic test for hardest versus easiest.** A reversed mining sort corrupts the experiment’s labels even when it improves the score. C2’s class-error direction test does not detect that substitution reliably. Use a small fixture with independently specified margins and expected selected examples; verify hardest/easiest ordering, per-class selection counts and deterministic tie handling.

10. **Suggestion — The verification grep necessarily fails its own expectation.** Step 2’s three approved wrappers contain `min_cost(`, which Step 9 says must produce no matches. Replace this with a check that permits calls inside the named wrappers and rejects calls elsewhere.

11. **Suggestion — Make the limits of the stage-0 report explicit.** The proposed evidence does not measure laundering, telephony, physical replay or wild-real false alarms. Preserve the stage-0 scope, but require the report to mark these as untested, keep V2-33 open pending its V2-01 benchmark requirement, and state the release blocker explicitly. The repository’s v2 rules support logging this diagnostic in `experiments/log.csv` while preserving v1’s submitted TSV.
