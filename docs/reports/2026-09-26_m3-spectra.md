Export for fusion: `outputs/detector_scores/spectra_aasist.csv` (`path, fold, split, score, logit`; **`logit` is the raw model margin, `score` its sigmoid, nothing fitted**), sidecar `spectra_aasist_summary.json`, raw companion `outputs/spectra/spectra_aasist_raw.csv`, run directory `models/m3_spectra_<stamp>/`.

## What M3 is

Spectra-AASIST (`lab260/Spectra-AASIST`, Hugging Face; XLS-R 300M front end, AASIST graph-attention back end, trained by its authors on undisclosed data) run **off the shelf, with no training**, over the NSA fold file (20,000 rows) and the test set (1,671 files). Its value for fusion is a second deep score whose training differs from the M1 probe, not a higher number than M1. The model's margin `synth_logit = logit_spoof − logit_bonafide` increases with synthetic likelihood; direction is checked on NSA inner rows before anything is exported.

## Input path (the same function scores every row)

`load_audio` (16 kHz mono) → `hearsay.embed.prepare_segment` with default arguments, i.e. the shared band match (7.25 kHz Kaiser low-pass matching the test set's 7.2 kHz wall, commit 133e536), silence trim, optional test-length crop, cap at 8 s → short-clip handling → 64,600-sample windows at 50% hop → pre-emphasis → model → mean of the window logits.

**Crop parity.** Fold rows (inner and holdout) are cropped to test-duration lengths with exactly the draws M1 and the handcrafted detector used (`test_duration_sampler(0)`, one draw per `nsa_train_sample.csv` row in order, offset seed = row index), so fusion sees the same audio per file across all three detectors. Test rows are scored whole. Without the crops, four in five test rows would be padded and almost no training row would be, which is the tiling seam M1 v2 removed.

**Short clips.** 81% of NSA test clips are shorter than one Spectra window (4.04 s; test median 3.41 s), so how a short clip is padded is the test condition. Three modes were measured on inner rows only: `repeat` (tile to one window, the model card's own `pad_random`, in-distribution for the model but a seam), `zero` (zero-pad to one window), `whole` (the clip at its own length; the AASIST positional table covers 8 s).

## Pilot: choosing the short-clip mode (CPU, 05:02–05:09)

First 400 fold rows (322 inner rows, 171 bona fide / 151 spoof; holdout rows skipped) plus the first 200 test rows, all three modes in one decode pass, 401 s at 0.77 s per clip on the loaded CPU (three forwards per short clip). No decode or model failures. 434 of 522 prepared clips were shorter than one window.

| Mode | Inner minDCF (π_synth = 0.3) | Inner EER | Inner AUC | Spoof / bona fide median margin | Test share with margin > 0 (prior ≈ 0.30) | Test share under the card's threshold |
|---|---|---|---|---|---|---|
| repeat | 0.0066 | 0.6% | 1.000 | +10.2 / −7.7 | 0.310 | 0.290 |
| **zero** | **0.0000** | **0.0%** | **1.000** | +10.4 / −6.5 | **0.265** | 0.260 |
| whole | 0.0000 | 0.0% | 1.000 | +11.5 / −7.3 | 0.280 | 0.275 |

Selection rule (frozen in P2): inner minDCF, ties within 0.02 broken by inner AUC, then `zero`. All three tied, so **`zero` was chosen**, the handoff's option (b). Two honest caveats: 322 rows make one bona fide false alarm worth 0.055 in normalized minDCF, so the pilot can only say "all three are near-perfect on inner rows"; and `repeat` is the in-distribution choice for the model while `zero` and `whole` are out of distribution, which the numbers did not punish here. Per generator on the inner rows, every DiffSSD generator scored minDCF 0.0 in `zero` mode, including `grad_tts`, `pro_diff` and ElevenLabs, the three the handcrafted detector is blind to.

**Level.** Spectra does not level-normalize its input. Within the bona fide class the margin is uncorrelated with clip peak level (Spearman 0.00), within the spoof class it rises with level (Spearman 0.36 for `zero`, 0.27–0.29 for the others). Level is doing some of the work on the synthetic side; it cannot create a false alarm on quiet real speech, but it is a shortcut to keep in mind if the test set's synthetic clips were normalized differently from DiffSSD.

## Direction baseline (untouched `scripts/spectra_direction.py`, raw path: no trim, no crop, no band match, repeat-pad)

300 inner rows (150 per class, seed 0, `outputs/manifests/nsa_inner_direction300.csv`), MPS, 05:19: AUC 1.000, EER 0.0%, median margin +10.5 for spoof and −7.7 for bona fide, EER threshold at a margin of 6.5, 0.43 s per clip (uncapped 5–9 s clips, up to 16 windows). The script's own gate passed. Raw scores: `outputs/spectra/nsa_inner300_scores.csv`. So the direction and the separation do not depend on the shared input path; the path is there for parity with the other detectors and for the test set's band, not to make Spectra work.

## Peak-normalization arm (rejected)

After the pilot's level flag, the main chat proposed scaling every prepared clip to peak 0.95 (Spectra sets `normalize_waveform=False`; training real audio peaks about 0.5, NSA test clips and some spoof generators about 1.0). The arm ran on MPS on the same 322 inner and 200 test rows, `zero` mode (`--peak-norm`, run `outputs/spectra/pilot/20260926-0517_pilot_peaknorm`):

| Arm | Inner minDCF | Inner EER | Inner AUC | LJ Speech bona fide minDCF | Test share with margin > 0 | Within-spoof Spearman(peak, margin) |
|---|---|---|---|---|---|---|
| raw (shipped) | 0.0000 | 0.0% | 1.0000 | 0.000 | 0.265 | 0.36 |
| peak 0.95 | 0.0331 | 0.6% | 0.9997 | 0.033 | 0.265 | 0.40 |

Rejected by the rule recorded in the spec (outside the 0.02 tie band, and the correlation did not drop). The correlation with the *pre-normalization* peak survived normalization, so level is a proxy for something else (the loud generators are also the easy ones), not the cue the model uses; normalizing only cost a little on the real side. Shipped configuration: `zero` mode, band match from `prepare_segment`, no level normalization.

**Disagreement with M1 v3 on the test set** (`submissions/20260926-0522_M1_…0518.tsv`, joined on filename, 1671 files): Spearman between the two score columns 0.569. At each detector's own midpoint (M1 probability 0.5, Spectra zero margin): both call synthetic 409, both real 1108, **Spectra only 80, M1 only 74**: 154 files (9.22%) where the two deep detectors disagree. A rank correlation of only 0.57 between two detectors that both separate the holdout well is the point of M3: they are wrong on different files, and a stacker can use that.

**Level** on all inner rows: within-spoof Spearman(peak, margin) 0.31, within-bona fide -0.07; the same picture as the pilot, and the peak-normalization arm above showed it is a proxy, not the cue.

**Caveat: the inner rows may be in-sample for Spectra.** The model's training data is undisclosed; LJ Speech, LibriSpeech and DiffSSD are public and plausible training corpora, and the inner rows score AUC 1.0. `meta.json` records `caveats.inner_rows_possibly_in_sample = true`. Fusion should not treat the `inner_oof` column of this detector as out-of-fold evidence the way it does for M1 and the handcrafted detector; the holdout (also DiffSSD and public real speech, so not immune), the test-set share and In-the-Wild are the readings that depend least on it. The draft-review score is the only fully independent check.

## What Spectra is blind to, and what this rung does not test

On our data Spectra trails M1 nowhere: every holdout group is at or under 0.012 minDCF. What it is blind to, we cannot see from labeled data we own: the two deep detectors disagree on 154 test files, the real side of In-the-Wild sits within 3.2 margin units of the boundary (median −3.2 against −6.3 on NSA real speech), and 13.8% of In-the-Wild spoofs fall under the NSA-derived minDCF threshold, so unseen generators under channel shift are where misses will come from. The level proxy (loud synthetic generators are the easy ones) is the one measured shortcut.

Not tested here, by construction of a scoring rung with nothing trained: robustness to codec laundering, telephony band-limiting and simulated replay (M5's augmentation is where those are measured), and physical replay (no hardware). The band match and the In-the-Wild readout are the only channel-shift evidence in this report.

## Notes for fusion (M4)

- Read the `logit` column directly and standardize it per detector on inner rows (commit 944380c). Spectra's margins run about ±10 to ±17; `logit(clip(score, 1e-4))` would saturate them to ±9.2 and lose the ranking in the bona fide tail where the minDCF threshold lives.
- `inner_oof` rows are not out-of-fold in any learned sense: nothing was fit, so inner and holdout are both out-of-sample for the model. The label keeps the file shape uniform with the learned detectors.
- NaN rows (decode or model failures) stay NaN in both columns for imputation and are counted in the summary sidecar.

## Reproduce

```bash
nice -n 10 uv run python scripts/score_spectra.py --limit 400 --test-limit 200 --pad-modes repeat,zero,whole --device cpu --threads 4 --name pilot
nice -n 10 uv run python scripts/score_spectra.py --manifest outputs/manifests/itw_stress.csv --name itw_stress --pad-mode zero --device cpu --threads 4
uv run python scripts/score_spectra.py --readout inner=outputs/spectra/pilot/<stamp>_pilot/scores_zero.csv stress=itw=outputs/spectra/itw_stress/scores.csv --out outputs/spectra/itw_stress/readout_provisional.json
nohup nice -n 10 uv run python scripts/score_spectra.py --pad-mode zero --device mps > outputs/spectra/score_spectra.log 2>&1 &
uv run python scripts/score_spectra.py --readout inner=outputs/spectra/spectra_aasist_raw.csv test=outputs/spectra/spectra_aasist_raw.csv stress=itw=outputs/spectra/itw_stress/scores.csv m1_tsv=submissions/<M1 v3 tsv> pilot=outputs/spectra/pilot/<stamp>_pilot/meta.json --final --out outputs/spectra/itw_stress/readout_final.json --merge-into models/m3_spectra_<stamp>/meta.json
```
The last command is how the In-the-Wild block, the M1 disagreement, the pilot table and the caveats got into the run's `meta.json` (as its `readout` block); the export itself ran without `--stress` so its end could not depend on a file another process was still writing. `--resume` restarts an interrupted full run from its checkpoint; `--max-chunks 1` is a dry run.
